# 视觉与低空智能 · 写作规范

本文是本号推文的唯一写作参考。规则冲突时以本文为准。

## 读者与定位

读者以计算机视觉、遥感、无人机、具身智能方向的工程师和研究者为主，同时常有不少跨领域读者。推文要写到两类人都能读：专业的人读到料，小白读得懂逻辑。

默认读者没读过 YOLO、CLIP 这些基础工作。每个术语第一次出现都给大白话解释，机制描述讲清楚"它在干嘛"，必要时配一个生活化类比。技术密度靠事实和数字撑，不靠堆术语。

说话人是一个查过材料、形成判断的人。不是官方新闻稿，不是 PR 通稿，不是百科全书。

## 硬约束（每条都会被检查）

1. **不写公式**。公众号不渲染 LaTeX，`$...$` `$$...$$` 会原样显示成源码。
2. **多数句子 20-30 字，一段最多两句**。手机端一行 20-30 字，段落一长就没人读完。一段写到第三句就换行分段，绝不让段落超过两句。超过 40 字的句子拆成短分句，其余照正常中文写。不要为求短把句子切碎。
3. **链接写裸 URL**。`[文字](url)` 在公众号里点不了。
4. **正文不用 `---` 或 `***` 分隔**，会产生多余 hr 标签破坏排版。用空段落分隔。
5. **表格一律用论文原表截图**。窄屏不放 markdown 表格，也不用代码块仿制（截图流程见「结构」）。
6. **数字必须能溯源**。每个数字写明官方出处（论文表格、官方博客），查不到出处的数字不写。核验在动笔前完成，核验过程不写进稿子。
7. **标题和摘要写在文件头部注释里，正文不写一级标题 `#`**。文件开头用 `<!-- title: ... -->` 和 `<!-- digest: ... -->` 记录定稿的标题与摘要（后台填的时候直接取用），正文从 hook 开始。
8. **小白可读**。术语第一次出现必须给大白话解释；机制描述不预设读者读过相关论文，必要时用生活化类比。
9. **AI 味零容忍**。见下面「禁止清单」。

## 动笔前第一关：材料够不够

**非虚构稿子靠材料撑，不靠辞藻。**动笔前在内部列一遍，至少 5 件具体材料：

- 论文里的数字、对比结果、消融结论
- 方法里的具体机制、模块、参数
- 部署、开源状态、复现条件
- 官方博客或仓库里读到的意外细节
- 和已有工作的关联点（`readings/`、`topics/` 里已读过的论文能接上的点）

五件材料要能组成一条实际过程，不能是五句相邻的道理。**凑不满就先去查**，查完仍不足就写短文，绝不用假例子和重复解释灌字数。

每件重要材料要记得来路。说不出路的内容不能用来托住事实段落。

## 说话位置

动笔前回答五个问题，不写进文章：

1. 谁在说这件事，凭什么知道，哪些地方只是推测
2. 什么事情让他现在想说
3. 手里有哪些能托住文章的东西
4. 他对哪一点有明确判断，依据是什么，到哪里为止
5. 读者看完上一段会追问什么

**没有亲历也能写**，靠事实、可核验的流程和推理，但不能说成亲眼见过。判断要敢下，也要标明是个人看法。

## 开头（前 3 句定生死）

第一段让读者知道这篇讲什么、为什么值得看。

- 用具体事实或反差开场。3B 模型打赢 7B、复现不了的论文只开源了一个替代品，这类反差最好
- 不用"近日""随着……的发展""近年来"
- 第一段不超过 3 句，不加【】等标记
- 段后紧跟封面图

自检：把标题给陌生人看，他读完第一段应该知道要不要继续。

## 标题

标题长短跟着内容走，**20-40 字**。短而狠优先：能用一个反差钩子说清的，就不堆背书和数字；字数是结果不是目标，别为凑长度硬塞信息。

### 四种常用结构

**A. 厂牌背书 + 机制 + 结果**

> 英伟达开源 Sol-H3：用 RSI 递归自改进给 MiniMax-H3 提速 30 倍，5 秒视频 1.4 秒出片

> 清华、字节开源全双工对话模型 ELLSA 2：会抢话、会附和，沉默时也有表情

机构名放前面（清华、字节、英伟达、小鹏、蚂蚁、阿里），自带信任和流量。

**B. 数字反差 + 疑问钩子**

> 3B 参数碾压 Gemini Pro：开源视觉大模型凭什么这么强大？

> Xiaomi-OCR-0：0.8B 小模型拿下 Top1，背后是 1.7 亿条数据

小模型、小数据、低成本干掉大模型大数据的反差，数字越具体越强。疑问钩子（凭什么、怎么做到的、居然）配反差用，不能空喊。

**C. 方案名 + 技术拆解 + 场景结果**

> 小目标检测新方案 YOLOMG | 运动差异图+双模态融合，复杂场景小目标检测依旧登顶 SOTA

技术拆解用 `+` 或短横线并列（一两个关键词，不超过三个），后面跟场景和结果。

**D. 痛点 + 硬机制**

> 最新论文 | WinARDet: 破解框重复循环，提升多模态大模型极密集场景检测能力

> 夯爆了！具身领域的 GroundingDINO 时刻，小鹏携手多所高校提出 GroundingPI

痛点用动词砸出来（破解、压制、砍掉、提速、堵住），别用"优化了""提升了"。

**E. 对手反差 + 机制 + 落点**

> YOLO迎来最强对手，VLX-Seek 把细粒度视觉感知做进端侧

拿知名老牌方案当锚点立反差，一句机制、一句落点收住。锚点要真在同一赛道（检测/感知），别拉郎配。

### 常用句式模板

- `[机构]开源[作品]：[一句话机制]，[具体结果]`
- `[数字][指标]碾压[大厂]：[作品]凭什么[反问]`
- `[小模型/少数据]拿下[第一]，背后是[数字]怎么[做到的]`
- `[方法名]：[破解/解决][痛点]，[能力提升]`
- `[动作]，[时间]拿到[数字]`

### 可用动词

开源、拿下、登顶、破解、砍掉、提速、压制、干翻、追上、甩开

### 栏目前缀

固定栏目可以在标题前加前缀，正文里不要再提：`最新论文 | `、`开源 | `、`论文 | `。

### 红线

- 不以作者名开头
- 不以"直接能发""轻松搞定""全都支持"这类虚词收尾
- 不空喊概念："新一代视觉语言模型解决方案"这种删掉
- 不用冒号连用两个（`A：B：C` 保留一个即可）
- 数字必须是真数字，编造的具体数字比没有数字更伤

每个词删掉后如果意思没变，那个词就是废话。

## 结构

**推文的章节结构严格沿用对应的 readings/ 解读文章**：章节名、编号、顺序、小节划分一一对应，从解读文章出发压缩语言，不另起炉灶自创结构。开头 hook 和封面图放在第一节之前；解读文章里内容太薄的章节可并入相邻章节，但不得打乱顺序；结尾附原文和代码链接。

- 语言风格按本规范处理：段落 1-2 行、术语大白话、去 AI 味，把解读文章的密度翻成小白能读的句子
- **章节标题只在专有名称（模型名、任务名、数据集名）保留英文，其余一律用中文**（例：`## 3. WeDetect 检测底座`、`### 3.2 数据引擎`），解读文章和推文两边的标题保持一致
- **论文表格用原表截图，且在解读文章阶段就已备好**：截图、裁剪、转 WebP 由 paperNotes Step 4 在写解读文章时完成并入仓 `readings/assets/<slug>/`（caption 一并保留，表头和首尾行不得切掉）。写推文**直接复用解读文章里的配图，且解读文章的配图一张不落全都要用上**（机制图、效果图、表格截图都算），**不再自己渲染裁剪转格式**；每张表图前配一段解说，说清跟谁比、赢在哪；**禁止用代码块仿制表格**
- 段落推进：一段最多两句，第三句起换行。一段只讲一件事，逻辑跳变就空行断开。因果链一步一段，不把背景、原理、结果挤进同一段。举完例空一行，判断单独成段

## 公式与专业内容

公众号不渲染 LaTeX，三种处理办法：

**1. 大白话替代**

> InfoNCE 损失本质上在做一件事：让配对的图文向量互相拉近，不配对的互相推远。温度系数控制拉近的力度。

**2. 公式截图**。论文里的公式直接裁出来当配图。截图同样由解读文章阶段按 paperNotes Step 4 备好入仓，推文直接复用，不自己渲染。

**3. 用数字讲**。公式复杂但结论简单时，只给结论。

> 按这个损失训 30 个 epoch，检测 mAP 从 32.2 到 39.4。

**代码块**：命令和关键配置可以贴，超过 5 行改文字描述。代码块只放代码，不放无关日志。

**术语**：第一次出现给人话解释，解释要落到"它在干嘛"（例：开放词汇检测，就是不用提前写死类别表，想到什么就能让模型找什么）。后文直接用。第一次出现的缩写写全称，如"视觉语言模型（VLM）"。

## 行内组件

排版支持 `**粗体**`、`` `行内代码` ``、`:::mark 高亮:::`、`:::red 文字:::`。用在真正需要强调的地方，不撒胡椒面：

1. **粗体**：一节内最关键的结论或数字，一章最多一两处
2. `:::mark 高亮:::`：最想让读者记住的句子，按内容需要用
3. `:::red 文字:::`：只标过时方案、官方否定的做法、明确的坑，没有就不硬用
4. `` `行内代码` ``：正文里的英文术语一律用行内代码（模型名、数据集名、任务名、模块名、`prompt` `token` `query` 这类技术词），命令、文件名、配置项也是；章节标题与图片说明里不加

标记跟着内容走，该强调就标。

## 句子层面

**主干先交出来**。先说人做了什么，再补原因、条件和例子。定语一长，读者要等很久才知道谁做了什么。中文里"一"的连用会把句子绕晕，能拆就拆成两三个短分句。

**句子跟着动作往后长**。一个动作带出新东西，下一句接着这件东西。指向清楚时不必每句重念主语。

**连词少用**。中文靠语序和事理相接，"因为…所以…同时…而且"能删一半就删一半。读不断的地方再补回来。

**动词不名词化**。"完成了对流程的优化"是模型腔，改成"把流程改顺了"。

**长短句搭配**。十个字的句子挨着三十字的句子，读着才有呼吸。全篇一个节奏会像在敲桌子。短句用于落地，长句用于展开。不要为求短把句子切碎，写完整句，让句号自然收束。

**具体细节必须有工作**。一笔价格能说明风险，一段原话能说明关系，一次失败能说明旧办法为何行不通。没来源、又不改变后文的细节全部不要——凌晨三点、第三根烟、桌上的冷咖啡这类装饰性细节只会加重 AI 味。

**留白**。动作、物件、原话已经传出情绪时就停一下，别追一句解释。读者能自己走完的两三步，留给读者。

**幽默来自降格**。宏大的说法碰到现实里的小麻烦，天然好笑。落差写出来就够，别另编笑话。

## 禁止清单

### 硬性禁令（命中即改）

- **翻案腔**：`不是……而是……`、`并非……而是……`、`不在于……而在于……`、`与其说……不如说……`、`表面……实际……`、`看似……实则……`、`不是 A，是 B`、`不是 A。而是 B`、`你以为……其实……`、`回头才发现`、`说到底`、`答案恰恰相反`、`A 不重要，重要的是 B`
  - 改法：直接从正面下判断，先给判断再给依据。清单只是举例，同一个动作换任何字面都算
- **破折号** `—` `——` `–`：一律不用，改成逗号句号
- **冒号**：只允许引出人物直接原话。"一句话总结：""核心是："这类提示性冒号禁止。网址、代码、机器字段除外。链接行的冒号（`原文：https://…`）保留
- **顿号罗列过密**：一个分句里顿号串三项以上并列。必须保留时改变其中一项的句法。模型档位、指标清单这类必须完整列出的，照原样留
- **序数词当小标题**：`## 一、` `## 第一、` 通篇编号，删掉编号留文字。本号惯用的 `## 1. xxx` 阿拉伯数字编号不在此列
- **起手式**："说白了""说穿了""先说结论"
- **相邻句结构同款**：连着几句逗号数、成分顺序、长度都一样，单看每句都通顺，连起来像填表。打散其中一句的句法
- **三项以上同构排比**：整齐划一的排比读着像填表
- **抽象名词配具体动词**抒情："时间保管细节""焦虑显出形状"
- **翻案位置的路标词**："更微妙的是""还有一层""只说对了一半""值得注意的是""需要指出的是""从某种意义上说"
- **段首零主语评论**：非首段以评论词开头且没有回指成分，补个"这"字
- **翻译腔五种**：`当……时`从句前置、过长前置定语、前置话题壳（"对于……来说"）、句首连接词当路标（"然而""因此"独立成段首）、"这意味着"式复述句
- **段落里靠连接词排队**："这也解释了""更麻烦的是""还有一个地方""当然""所以"
- **「」批量造金句**：「」括起来的短语超过三处，一篇都在批量下定义。留最狠的一两处
- **统一短段鼓点**：连续四段都是单句短段，读着像排队喊结论。合并其中两段，或让其中一段多说一句
- **理想化职业人格的喻体**："像一位智慧的导师""一个永不疲倦的初级审查员"。换成这东西实际做了什么。比喻本身不算 AI 味，具体的人当喻体（"像一个老师傅"）照留
- **比喻扎堆**：八百字里三套以上借喻（升温降温、战场、赛道、仓库这类）。换掉其中一层，或改成具体描述
- **具体数据被概括词盖掉**："新系统实现了效率的提升。处理时间从两小时缩短到四十分钟。"把已有的数字提到概括词的位置。原文没有数字时不许自己编，只恢复动词

### AI 味词汇（出现即改）

**通用**："值得注意的是""值得一提的是""总而言之""综上所述""不难发现""由此可见""毋庸置疑""不可否认""让我们一起来看看""首先其次最后""随着科技的飞速发展""在人工智能的浪潮下""为读者朋友们带来""本文将深入解读""可以说""不容忽视""不难理解"

**技术圈黑话**："范式升级""降本增效""深度赋能""生态构建""技术壁垒""护城河""全链路""全场景""精准对齐""维度重塑""能力跃迁""行业引领""致力于""全方位""多层次""一站式""赋能""抓手""闭环""沉淀""反哺""拉通""心智"

**组织黑话**："底层逻辑""顶层设计""认知跃迁""能力建设""能力沉淀""价值释放""技术底座""公共底座""内容矩阵""组合拳""迭代闭环""打开想象空间""结构性机会""关键命题""深层逻辑""技术主权""单点风险""主脊柱""材料锚点""认知增量""商业闭环""价值闭环"

**抒情词**："安放""抵达""微光""褶皱""丰盈""滚烫""轻盈""赤裸""剥开"。写具体事物时保留，给抽象概念穿衣服时删掉

**洞察路标**："真正""本质上""更深层次""归根结底""换句话说""不可否认""核心是""关键在于""这意味着"

### 禁用句式

- `不是 A，而是 B` → 直接说 B
- `与其说 A，不如说 B` → 直接说 B
- `这不仅仅是 A，更是 B` → 直接说 B
- `A 不仅仅……更是……` → 留后半截

底层问题都是先否定再肯定，读着像申论。正常人说话直接给结论。

## 怎么改

脚本只报警，改还是人改。改的时候守四条：

1. **白名单式**。只改「硬性禁令」「AI 味词汇」「禁用句式」里列出的问题。没命中任何规则的句子逐字保留，不顺手润色
2. **最小改动**。一句命中多条规则，改到不命中为止就收手。不替换没问题的词，不动语气、详略、信息密度
3. **信息守恒**。姓名、机构、数字、日期、引语、出处、因果、限定词（"可能""通常""据说"）一个都不能动。改写后的每个实词都要能在原文指出出处，指不出来就是新增，撤销
4. **框架不动**。标题层级、章节顺序、段落顺序、列表、表格、引用、代码块的位置原样保留。不概括、不扩写、不删观点

拿不准的留着。宁可留一处 AI 味，也不要改错意思。

## 配图

正文配图在解读文章阶段已按 paperNotes Step 4 备好入仓，推文直接复用，不自己取材渲染。

1. 开头段之后放封面图，硬性要求
2. 封面图走 `gzh-handdrawn` 出提示词、`qianliu-img` 出图，比例 21:9，用 `img-pro`；千流云实际返回什么比例就用什么，不做后期 pad/裁切
3. 解读文章的配图一张不落全都要用上，图片紧跟在说明它的那段之后
4. 图文对应：每张图前后 100 字内有相关文字，不放孤岛图
5. 图片 URL 必须真实（curl 验过能访问），禁止按路径规律猜
6. 配图不够时用文字描述替代，不硬凑密度

## 结尾

一句态度收尾，不总结全文。

- 禁止"总之""综上所述""希望这篇文章对你有帮助"
- 可以给行动点：去跑 demo、看代码、关注哪个方向

## 落盘前检查

- 文件头部有 `<!-- title: ... -->` 和 `<!-- digest: ... -->` 注释，正文不写一级标题 `#`
- 除 Star 数外不把数字转 K（分辨率、帧率、显存、参数量等参数保持原样）
- 代码/项目链接放在最后附一次
- 全文无 `$`、`$$`、`[文字](url)`、`---`、`***`

## 成稿自检

| 检查项 | 标准 |
|--------|------|
| 标题 | 20-40 字，有背书/反差/钩子，短而狠，冒号不连用 |
| 摘要 | ≤120 字，是钩子不是导语复读 |
| 公式 | 全文无 `$` `$$`，有公式处已改大白话或公式截图 |
| 链接 | 全部裸 URL |
| 分割线 | 正文无 `---` `***` |
| 段落 | 每段不超过两句，绝大多数 1-2 行，无 4 行以上长段 |
| 短句 | 多数句子 20-30 字，无 40 字以上的长句 |
| 数字 | 可溯源，出处已标 |
| 表格 | 全部原表截图，无 markdown 表格，无代码块仿制 |
| 配图 | 全部云端 URL，本地路径 0 处，图文对应，解读文章配图无遗漏 |
| 禁止清单 | 硬性禁令 0 处，AI 味词汇 0 个，禁用句式 ≤1 次 |
| 获得感 | 读者读完能说出至少 3 个新点 |
| 字数 | 1400-2500 |
