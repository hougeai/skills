# gzh-writer-cv · 视觉与低空智能公众号推文

读者是计算机视觉、遥感、无人机、具身智能方向的工程师与研究者。技术密度高，不需要科普铺垫，但也没耐心读晦涩长文。他们点进来是因为想看清一件事值不值得跟。

## 铁律

1. **不写公式**。公众号不渲染 LaTeX，`$...$` `$$...$$` 会原样显示成源码。需要公式的地方改用两种办法：大白话把公式在做什么说清楚，或者直接截论文里的公式图（`pdftoppm` 裁出来当配图）。InfoNCE 这类东西写"让配对的图文向量互相拉近、不配对的互相推远"，读者能懂，公式源码不能。
2. **多数句子 20-30 字，一段 1-2 行**。手机端一行 20-30 字，段落一长就没人读完。超过 40 字的句子拆成短分句，其余照正常中文写。按逻辑跳变点拆段，别按句子数拆。
3. **链接写裸 URL**。`[文字](url)` 在公众号里点不了。所有链接以 `https://...` 纯文本形式给出。
4. **正文不用 `---` 或 `***` 分隔**，会产生多余的 hr 标签破坏排版。用空段落分隔。
5. **表格改成分行**。窄屏表格横向溢出，改成"指标名 + 数字"逐行写，或用列表。
6. **数字必须能溯源**。来自论文正文、官方博客、仓库 README 的原文数字，注明出处；官方只给了图片形式的表格就写明"官方未给文本值"。不确定的数字不写。
7. **AI 味零容忍**。禁止清单见 references/style-guide.md，成稿后用 scripts/check_prose.py 自检。

## skill 构成

```
gzh-writer-cv/
├── SKILL.md                    # 流程、铁律、自检清单
├── references/style-guide.md   # 唯一写作参考（读者定位、材料关卡、标题、结构、句法、禁止清单、怎么改）
└── scripts/check_prose.py      # 成稿硬禁令检查脚本（只报警）
```

写作部分自包含：检测靠 `scripts/check_prose.py`，改法靠 `references/style-guide.md`。配图环节借两个外部 skill，`gzh-handdrawn` 出提示词，`qianliu-image` 出图。

## 流程

### Step 1 备料

- 首选素材是 `readings/YYYY-MM-DD-<slug>.md` 解读文章（里面的数字已核实过）
- 需要补一手来源时按 paperNotes 的来源优先级取：arXiv LaTeX > 官方博客 > 仓库 README > 公众号文章
- 列材料清单：至少 5 件具体材料（数字、机制细节、部署信息、开源状态、有意思的对比），凑不满就先补材料或写短文
- 查重：`search_file` 看 `gzh/` 下有没有同 slug 的推文

### Step 2 出标题

出 3 个候选，每个附 1-2 句理由，等用户挑。标题打法和红线见 references/style-guide.md。

### Step 3 撰文

**唯一写作参考是 `references/style-guide.md`，动笔前读一遍**（读者定位、材料关卡、标题打法、结构骨架、公式处理、段落与句子规则、禁止清单都在里面）。

章节跟着素材走。参考维度是清单不是脚本，素材没有的维度砍掉，有实料但清单没列的可以加。

### Step 4 机器检查与清理

```bash
python3 scripts/check_prose.py gzh/YYYY-MM-DD-<slug>.md
```

脚本只报警不改文。覆盖两类：

- **公众号渲染约束**：公式源码、markdown 嵌入链接、`---` 分隔线、本地图片路径、超过 4 行的段落、超过 40 字的句子、字数区间
- **AI 味与句法**：翻案腔、破折号、提示性冒号、顿号罗列、同构排比、相邻句同款、名词化、序数小标题、拟人喻体、概括词盖数据、段首零主语评论、翻译腔五种，以及黑话、模型路标、抒情词等词表命中

按提示回改，改法见 references/style-guide.md 的「怎么改」：只改命中处，最小改动，数字和事实一个不动。改完重跑，直到「需要修改」清零、「需要人工判断」逐条看过。

### Step 5 自检

脚本查不了的只剩这几项，逐条过一遍：

| 检查项 | 标准 |
|--------|------|
| 标题 | 25-45 字，有厂牌背书或数字反差，冒号不连用 |
| 摘要 | ≤120 字，是钩子不是导语复读 |
| 数字 | 每个数字可溯源到原文，出处已标 |
| 配图 | 全部云端 URL；图文对应，图前后有说明文字 |
| 获得感 | 读者读完能说出至少 3 个新点 |

公式、链接、分割线、段落、句长、AI 味、字数这些 Step 4 已经查过，不在这里重复。

任何一项不过就回去改，改完重跑脚本。

### Step 6 落盘与推送

**落盘**：`gzh/YYYY-MM-DD-<slug>.md`，`<slug>` 与解读文章文件名一致。

**配图**分两路：

**A. 论文原图（正文插图）**
- 取材优先级：论文 LaTeX 里的 figures 目录 > 官方博客图片 URL > 论文 PDF 里的图表截图
- 下载境外源超时时加代理：`export https_proxy=http://127.0.0.1:8123`（clone 仓库同理）
- LaTeX 图表常是 .pdf 矢量图，先转位图：`pdftoppm -jpeg -r 300 figure1.pdf fig1`（要透明底用 `-png`）
- 每张图传 gzh-hub 图床换云端 URL，回填进 md，最终 md 里不许留本地路径
- 配图不够时用文字描述替代，不编 URL

**B. 封面图（必须有）**
- 加载 `gzh-handdrawn` skill 生成封面提示词（21:9 封面）
- 提示词拿到后调 `qianliu-image` skill 出图，提示词原样传过去
- 出图档位用 `img-pro`，比例 21:9（比例不在支持列表里时千流云内部会处理）
- 千流云返回的 `data[0].url` 是永久公网地址，直接写进 md 当封面图，不用再传 gzh-hub
- 需要 API Key（`QIANLIU_API_KEY`，形如 `sk-ql-xxxx`）时问用户要，没有就让用户到 https://console.qlcloud.top/keys 创建
- 封面图放在开头段之后，md 里写 `![封面](url)`；同时留作推送时的 `cover_url`

**推送**：
- 推送前调 gzh-hub 3.1 拿本号 `mp_id`，3.2 拿 news 主题 `theme_id`
- news 体裁 `cover_url` 必填，用 B 路出的封面图 URL
- 把标题、摘要、配图数、字数报给确认后再推
- **只推草稿箱**，正式发布由用户在后台操作
