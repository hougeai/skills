# 摄入与缺口诊断

当源材料或输出要求不完整时使用本文件。

## 接受的输入

- 文章、随笔、通讯、博客
- Markdown 笔记
- DOCX 文档
- PDF 文档
- 已有 PPTX 演示稿（仅提取源内容与视觉意图）
- 课程大纲
- 讲义或视频脚本
- 粗糙想法或要点
- 一个主题加目标受众

## 先提取

从源材料识别：

- 主题：配图组讲什么
- 受众：谁需要理解
- 场景：教学、销售、汇报、工作坊、社媒内容、内训
- 目标：受众看完应相信、理解或做什么
- 核心论点：配图组必须保留的少数陈述
- 概念：需要解释的术语
- 流程：步骤、阶段、机制、循环或序列
- 对比：旧/新、错/对、前/后、方案 A/B
- 证据：例子、数字、案例、引用、观察
- 风险：需要用户确认的论点

## 默认值

安全时使用：

- 受众：有中等技术熟悉度的中文学习者
- 场景：教学或公开讲解
- 图数量：单篇文章 4–8 张（含 1 封面 + 若干正文插图），长文不超过 9 张，短文 1–3 张
- 深度：实用概念讲解，非学术证明
- 风格：手绘中文公众号插图（提示词锁定）
- 产出：直接输出生图提示词；用户要规划时给蓝图
- 公众号视觉拆分：用户既要封面又要正文时，封面 21:9 + 正文插图 16:9

## 仅对关键缺失提问

仅当答案会实质改变配图组时才问，最多 1–3 个简洁问题。

问当：

- 主题模糊。
- 受众深度会改变语言层级。
- 使用场景未知且影响结构。
- 用户要商用交付但只给了粗糙主题。
- 源材料含看似重要但无支撑的论点。
- 用户给了严格图数量或交付格式但缺失。

不问当：

- 能选合理默认并继续。
- 缺失细节只影响润色，不影响结构。
- 用户明显想要初稿。

## 缺口诊断输出

需要提问时，把默认与缺失选择框定好：

```text
我可以先按"中文技术讲解，面向有基础的新手，10 张图左右"处理。
但有一个决定性信息会影响结构：这套配图是用于教学、销售说明，还是公开分享？
```

## 源材料充分度

- **充分**：有论点、若干要点、例子或流程、结论。
- **单薄但可用**：有论点与要点但例子少。继续并标注假设。
- **不足**：只有一个主题或口号。询问目标、受众与 3–5 个原始要点。
